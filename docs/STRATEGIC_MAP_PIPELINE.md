# Strategic Map Pipeline

## Representation

The campaign map is a province graph with visual geometry, not a giant gameplay tile grid.

Each province definition contains:

- Stable ID.
- Simplified polygon or multipolygon reference.
- Adjacency edge IDs.
- Terrain/climate tags.
- Center and label anchors.
- Settlement/site IDs.
- Optional coast, river, route, and elevation references.
- Historical provenance.

The simulation uses the graph. The renderer uses geometry and prepared textures.

## Source strategy

Potential source layers must be imported through a documented, licensed pipeline. Useful categories include:

- Modern coastlines/physical geography from public-domain Natural Earth data.
- Ancient place identifiers and gazetteer points from Pleiades under its published license.
- Carefully reviewed OpenHistoricalMap extracts where feature-level licensing and quality are acceptable.
- Original province boundaries drawn for gameplay.

Historical political boundaries around 84 BCE are reconstructed gameplay boxes, not surveyed borders. Store confidence and source notes; do not imply false precision.

The current default pack is generated by `pnpm map:build` from Natural Earth 50m land into 2° land cells (`packages/sim-core/src/maps/earth84bce.json`, 4063 provinces, content version `earth.84bce.5`). Political boxes and named seats live in `tools/map/earth-84bce-politics.mjs`. Attested polities and tribal belts take priority over cultural regions; leftover land uses numerical names (`Territory 0001`). Cultural factions use `faction.culture.*` and `layer: "cultural"`. The renderer colors every owner; fog only hides operational intel (ADR-0006). Zoom LOD lives in `packages/sim-core/src/maps/earthGeometry.ts`: far zoom merges 4×4 owner blobs, mid zoom uses 2×2, near zoom draws every territory. Labels are collision-culled and stay a constant screen size; `Territory NNNN` only appears after a close zoom. Hit-testing always uses the fine cell under the cursor. Wheel zoom is exponential and centered on the pointer. WASD or arrow keys pan; +/− zoom; H or Recenter frames the player capital. Selecting an army or province from the side list eases the camera there. The first view opens on the chosen people's capital, not always Latium. Earth saves whose province count or content version does not match the current pack are rebuilt instead of painted onto the new grid.

## Build pipeline

```text
source geodata
→ normalize CRS
→ clip to theater
→ clean geometry
→ draw gameplay province boundaries
→ assign stable IDs
→ simplify into LODs
→ calculate adjacency
→ calculate anchors
→ validate topology
→ export compact runtime geometry
→ rasterize terrain/ownership helper textures
```

This is an offline toolchain, not work performed in the browser at startup.

## Runtime layers

1. Terrain base chunks.
2. Rivers/routes/coasts.
3. Province ownership/control overlay.
4. Fog/intelligence overlay.
5. Armies/settlements/sites.
6. Labels based on zoom.
7. Selection, previews, and alerts.

## LOD

Prepare multiple geometry and texture levels.

- Far zoom: theater chunks, major labels, aggregated armies.
- Mid zoom: provinces, routes, settlements.
- Near zoom: local features and detailed icons.
- Tactical maps are separate scenes.

Cull by camera bounds plus margin. Avoid thousands of live text objects.

## Selection

Options:

- Point-in-polygon against a spatial index.
- Low-resolution province-ID lookup texture.
- Simplified hit polygons.

Selection code returns a province ID. It never determines game rules.

## Adjacency

Edges are first-class data:

```ts
interface ProvinceEdgeDefinition {
  id: string;
  from: string;
  to: string;
  kind: "land" | "river-crossing" | "sea" | "mountain-pass";
  movementCost: number;
  seasonalTags: string[];
  routeId?: string;
}
```

Validate reciprocal edges unless directionality is intentional.

## Map tests

- No duplicate province IDs.
- No invalid geometry.
- Required provinces have anchors.
- Every simulation adjacency references valid provinces.
- Reachability expectations for the scenario.
- No unintended overlaps/gaps above tolerance.
- LOD preserves province identity.
- Runtime bundle stays under budget.
